# Tetragon 이벤트 전송 모듈

## 목표와 경계

JSONL 파일의 이벤트 한 줄을 [API 계약](../docs/api-contract.md)의 수신 봉투에 넣어 HTTP로 전달한다. **원본 변환·경고 판정·AI 호출은 하지 않는다.** 현재 구현은 없으며 main.py를 작성한다.

## 입력과 실행 형태

환경변수는 [개발 환경](../docs/local-development.md)을 따른다.

- `main.py --follow`: TETRAGON_LOG_PATH를 열어 **현재 끝부터** 새 줄을 읽는다. 이전 기록은 보내지 않는다. 현재 Tetragon 출력을 읽는 경로이며 source=live.
- `main.py --replay PATH`: 제공한 JSONL을 처음부터 끝까지 한 번 읽고 종료한다. 실제 기록을 재생해도 source=sample.
- 두 모드는 동시에 사용할 수 없다. 모드가 없거나 follow 파일이 없으면 사용법·경로 오류를 출력하고 종료한다.

## main.py의 처리

1. INSTANCE_ID와 EVENTS_URL 확인, HTTPX Client 한 개 생성(요청 5초 제한).
2. 빈 줄은 건너뛰고 완결된 한 줄을 JSON 객체로 읽는다.
3. follow에서 마지막 줄이 아직 끝나지 않았으면 다음 쓰기까지 보관한다. replay에서는 파일 끝의 마지막 JSON에 개행이 없어도 해석한다.
4. 성공하면 `{instanceId, source, rawEvent}`를 POST한다. 201만 전송 성공으로 센다.
5. JSON 오류·객체가 아닌 입력은 줄 번호와 원인만 기록하고 다음 줄로 간다. 원본 전체를 로그에 복사하지 않는다.
6. HTTP 4xx/5xx 또는 타임아웃은 실패 개수와 상태를 남기고 다음 이벤트로 진행한다. 자동 재시도하지 않는다.
7. follow는 EOF에서 0.2초 정도 기다린다. 파일 교체·크기 축소를 감지하면 메시지를 남기고 종료한다. 자동 회전 복구는 범위 밖이다.
8. replay 종료 시 성공/실패/건너뜀 개수 출력. 실패나 잘못된 JSON이 있으면 0이 아닌 종료 코드. Ctrl+C는 연결과 파일을 닫고 종료한다.

순차 전송으로 시작한다. 무제한 메모리 큐나 병렬 전송은 추가하지 않는다. 이 방식은 네트워크 장애에 이벤트가 손실될 수 있고 파일 재생 시 중복 저장될 수 있다. 완전한 전달 보장을 주장하지 않는다.

## 백엔드와의 연결

201 응답의 id는 진단에 사용할 수 있다. reportedAction/status 등은 전송기가 만들어 보내지 않는다. 원본 스키마가 달라져도 봉투 형식은 유지한다. 시연 환경이 아닌 다른 프로세스의 이벤트도 섞일 수 있으므로 Tetragon 담당자가 정한 관찰 범위와 시연 인스턴스의 의미를 확인한다.

## 확인

- 직접 만든 sample JSONL 1건 → source=sample로 저장되고 원본이 그대로 보존됨.
- 올바른 줄 사이의 잘못된 JSON → 오류를 기록하고 뒤의 정상 이벤트 전송.
- follow 시작 전 줄은 전송 안 함, 시작 후 완성된 새 줄은 1회 전송.
- 백엔드 중단 → 타임아웃/실패 로그, 성공했다고 표시하지 않음.
- 실제 Tetragon 출력 → live 이벤트가 화면에 도착. 예시 입력 성공과 구분해 기록.

실행 명령 예시는 아직 프로그램이 존재하지 않으므로 구현 후 검증한다.
