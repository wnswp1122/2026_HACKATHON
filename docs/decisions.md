# 현재 개발 결정

## 2026-10-31 사용자 확인

- SaaS 구조의 로컬 MVP를 구현한다. 기존 약 5시간은 확장 범위의 완료 보장으로 사용하지 않는다.
- 초기에는 사용자가 클라이언트, 팀원이 SaaS·프론트를 맡았으나 같은 날 추가 요청으로 사용자가 전 범위를 맡도록 변경했다.
- 게시판은 프론트 없는 간단한 CRUD API + SQLite다. 메모장·health-only 서버 계획을 대체한다.
- Tetragon은 별도 로컬 Linux VM에서 실제 관찰·정책 대응을 검증한다.
- SaaS는 단일 FastAPI 서버의 모듈 분리 + PostgreSQL이다. 메모리 최근 1,000건 설계는 폐기한다.
- 프론트는 React·TypeScript·Vite·Recharts다. 기본 HTML 정적 화면 설계를 대체한다.
- 수집은 보안 이벤트 중심이다. 게시판 글/DB, CPU·메모리·HTTP 성능은 보내지 않는다.
- AI는 사용자가 시간 범위를 선택해 고정한 데이터와 대시보드 캡처를 함께 분석한다. 캡처는 SaaS 프론트가 만든다.
- AI의 정책 자동 수정·배포·명령 실행은 제외한다. 실제 대응 결과는 이벤트 action과 분리한다.

## 데이터 계약과 작업 순서

[데이터/API 계약](api-contract.md)을 사용자 서버→SaaS의 단일 기준으로 사용한다. schemaVersion/messageId/instanceId/source/rawEvent, 토큰 인증, DB 저장 후 ACK, 메시지 중복 처리를 포함한다. 제한 재시도는 영속 큐나 무손실 전달이 아니다.

사용자 요청 순서: 문서·데이터 관련 Markdown 지침 반영 및 푸시 → 개발환경과 프레임워크 초기 구성 준비·검증·재현 설정 푸시 → Orca에서 사용자 담당 작업 3개 실행. [클라이언트 개발 지침](client-development.md)을 따른다.

기능별 PR과 로컬 검증 후 푸시를 사용한다. 자동 머지는 요청하지 않았다. SaaS·프론트도 아래 추가 요청에 따라 별도 Orca 작업으로 구현한다.

## 검증 상태

환경 검증은 [개발 환경](local-development.md), 기능 결과는 각 담당 README와 PR에 기록한다. 코드·실제 Tetragon 정책·실제 SaaS 수신·AI 호출 완료는 문서 존재만으로 주장하지 않는다.

## 프레임워크 초기 구성 추가 요청

Orca 기능 개발 전에 게시판 FastAPI 앱·SQLite 연결·Dockerfile, 전송기 HTTPX 환경·설정 검증·진입점을 준비한다. 설치한 가상환경/VM 자체는 Git에 넣지 않고 의존성 lock, VM 설정, 실행 방법을 푸시한다. CRUD·정책·실제 전송은 이후 각 작업에서 구현한다.

## 개발 기반 검증 결과

2026-10-31 FastAPI health/SQLite, HTTPX 설정 검증, 두 Docker 이미지 실행, 전용 Linux VM/Docker/BTF 및 Tetragon 기본 exec export를 확인했다. 세부 버전·명령·검증 범위는 [개발 환경](local-development.md)에 있다. 실제 정책 대응·전송·CRUD는 후속 Orca 작업이다.

## SaaS·프론트까지 범위 확대

사용자가 남은 컴포넌트도 직접 맡아 Orca에서 병렬 개발하도록 요청했다. 기존 세 작업은 유지하고 saas-core(DB·수신·백엔드 기반), dashboard-data(조회·집계·스냅샷), ai-analysis(캡처·AI 요청·지침), dashboard-frontend(프레임워크 세팅·화면) 네 작업을 추가한다. DB와 수신을 같은 작업에 묶어 트랜잭션·유일성 제약 소유를 일치시킨다. 파일 소유·DB/모듈 연결·프론트 API는 [병렬 개발 기준](saas-parallel-development.md)에 정의한다. 문서 기반 푸시 뒤 새 작업을 시작하며, 기능별 로컬 검증·커밋 후 결과를 전달한다. 자동 머지는 하지 않는다.

## Tetragon용 5개 화면 추가

제품 소개는 **AI 기반 서버 보안 모니터링·분석 플랫폼**으로 통일한다. 원본 Figma 5개 화면은 보존하고 같은 페이지 아래에 동일한 디자인·포맷의 Tetragon용 5개 화면을 추가한다. 현재 구조는 확장 가능하지만 파일/네트워크 정규화·센서 상태·고정 리플레이·위치 정보·5개 화면 연결은 추가 작업이다. 사용자가 기존 Orca 워크트리의 현황 확인과 수정 지시를 요청했다. 후속 책임·계약·검증은 [5개 화면 구현 계획](tetragon-screen-plan.md)을 따른다. 기존 이벤트 v1 봉투와 AI 안전 요약 계약은 유지하며, 센서 상태는 별도 수신·저장한다.

## AI 제공자 전환

OpenAI 크레딧 소진으로 신규 분석이 중단되어 Gemini Developer API로 전환한다. 서버 설정은 `GEMINI_API_KEY`·`GEMINI_MODEL`을 사용하며 OpenAI로 자동 우회하지 않는다. 고정 스냅샷·PNG, 결과 JSON과 DB 구조·잠금·성공 결과 재사용은 유지한다. 기존 OpenAI 성공 결과도 그대로 조회한다. 무료 제공 모델의 사용 한도와 데이터 이용 조건은 [공식 요금표](https://ai.google.dev/gemini-api/docs/pricing)를 따른다. 이번 전환은 실제 외부 호출 없이 검증하며, 모델의 분석 성공·품질은 키 설정 후 확인한다.


## 이벤트 상태 디자인 · 2026-10-31

- 이벤트 표시를 `observed` → **안전 / 파랑(#3b82f6)**, `attention` → **위험 / 빨강(#ef4444)**으로 통일한다. 필터·로그·집계·차트·스냅샷에서 같은 이름과 색상 변수를 사용한다.
- API·DB의 상태값과 분류 조건은 유지한다. 여기서 안전은 등록된 경고 정책에 일치하지 않는 이벤트의 UI 분류이며, 실제 보안 검증 완료를 뜻하지 않는다. 위험은 정책 일치 이벤트의 UI 분류이며 공격·차단 성공을 확정하지 않는다. 센서 준비 상태의 `unknown`·`warning`·`error`는 별도 상태로 유지한다.
- 개요의 위험 건수와 최근 위험 이벤트 최대 4건을 지구본 위에 표시하고 각 항목에서 원본 상세로 이동한다. 전체 위험 이벤트 조회는 기존 상태 필터를 사용한다.


## 위험 이벤트 전후 조사 · 2026-10-31

- `/replay`는 재생 시연보다 위험 이벤트 전후의 시간순 기록을 조사하는 화면으로 사용한다. 첫 위험 이벤트를 기본 선택하고 실제 기록의 프로세스·파일·통신 대상을 자연어로 보여 준다. 실행 식별자는 접힌 기술 정보로 옮긴다.
- 시간축 재생·일시정지·배속·시점 이동과 고정 조사 ID 복원은 유지하되 보조 기능으로 둔다. 저장 집합을 라이브 폴링이나 필터 변경으로 교체하지 않는다. 설명에 인과관계·공격 확정·차단 성공을 추가하지 않는다.
- 준비 점검의 정책은 Tetragon의 관찰·대응 규칙을 뜻한다. 로드 상태와 실제 대응 성공, 이벤트 경고 정책명 분류는 구분한다.

- 지구본의 IP·연결선은 실제 연결 집계의 `attentionCount > 0`이면 빨강, `0`이면 파랑이다. 같은 좌표의 표식이 겹치면 위험이 우선한다. 위험 건수가 없는 구형 응답은 미확인 색상으로 처리하며, 위치 미등록 IP는 좌표를 추측하지 않는다.

- 새 전후 조사는 같은 서버·출처·기간에서 상태·유형·프로세스·정책 필터를 제외해 전체 흐름을 고정한다. 위험 필터 때문에 직전·직후의 일반 기록이 사라지는 것을 방지한다. 저장된 기존 조사 복원은 원래 범위를 유지하고, 전후 목록·이전/다음 이동은 선택한 이벤트와 같은 서버로 한정한다.

- 24시간 sample: `scripts/seed_sample_history.py`로 합성 이벤트를 명시적으로 추가한다. 수신 시각도 과거로 분산하기 위해 DB에 sample 행만 저장한다. KP/CN/RU 좌표는 문서용 IP에 부여한 가상 위치이며 국가 자체를 위험 판정에 사용하지 않는다. `sample-risk-network`의 네트워크 매핑은 source=sample에만 허용한다.

## sample 환산 집계와 선택 이벤트 AI

사용자 요청에 따라 sample은 대표 원본을 유지하면서 서버별 초당 100건 규모로 환산한다. 추이는 `건/초`로 표시하며 상세·조사·Snapshot/AI는 대표 원본을 사용한다. [시연 집계 범위](service-sample.md)를 따른다.

위험 전후 조사에서 위험 목록 요약과 선택 이벤트 분석을 Gemini로 제공한다. 전체 이벤트는 구조화된 항목으로 표시한다. 전체 경로·IP·원본 인자를 제외한 제한된 텍스트 분석을 기존 Snapshot+PNG 경로와 분리한다. [전송·저장·검증 범위](investigation-ai.md)를 따른다. 프로세스 트리·관찰 통신 관계는 사용자 요청으로 프론트 화면과 조회에서 제거한다.
