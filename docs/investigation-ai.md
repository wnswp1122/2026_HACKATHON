# 위험 전후 조사 AI

저장된 조사(`/replay`)에서 사용자가 버튼을 눌렀을 때만 Gemini에 요청한다. 전체 이벤트 흐름은 유형·프로세스·대상을 표시하며 AI로 모든 기록을 문장화하지 않는다.

`POST /api/replays/{replayId}/analysis`의 JSON body는 `{}` 또는 `{"eventId":"UUID"}`다. 전자는 발생 시각순 위험 이벤트 최대 20건을 자연어로 요약한다. 후자는 해당 조사에 실제 포함된 선택 이벤트와 같은 서버의 앞뒤 3건을 분석한다. 응답은 replayId, eventId(목록 요약은 null), model, createdAt, result이며 result에는 summaries[{eventId,summary}], facts, hypotheses, checks, limitations가 있다.

AI에는 이벤트 유형·시각·출처·분류·보고된 대응, 프로세스/부모의 파일명, 접근 대상 파일명, 네트워크 동작·프로토콜·목적지 포트·정책명만 전송한다. 전체 경로·IP·명령 인자·실행 식별자·원본 JSON·파일 내용·캡처는 전송하지 않는다. 문자열은 지시가 아닌 관찰 자료로 다루고, 공격·유출·차단 성공을 단정하지 않도록 요청한다. 이 API는 기존 Snapshot+PNG 분석과 분리된 텍스트 분석이며 기존 Snapshot의 입력 계약은 바꾸지 않는다.

성공 결과는 `replay_analyses`에 조사·대상·지침 버전별로 저장한다. 같은 대상 재요청은 저장 결과를 반환한다. DB에 `backend/schema.sql`의 해당 테이블이 필요하다. 로컬 개발 DB에는 적용했다. 실패·시간 초과·키 미설정은 오류로 표시하며 가짜 결과를 생성하지 않는다. 생성된 요약의 이벤트 ID 집합도 요청 대상과 일치해야 저장한다.

로컬 확인: 모델 응답을 대체한 HTTP 전송으로 위험 10건 요약, 선택 이벤트 전후 7건, 성공 캐시 재사용, 대상 멤버십·입력 제한, 시간 초과 오류, 기존 Snapshot 경로를 확인했다. 실제 Gemini 호출·분석 품질과 브라우저 조작은 확인하지 않았다.

발표용 sample은 실제 모델을 호출하지 않고 서버가 이벤트 유형·프로세스·정책·인접 기록에 맞춘 예시 분석을 즉시 반환한다. 화면에서 시연 요약/예시 분석으로 구분하며 sample 조사에서는 자동으로 불러온다. live는 명시적 버튼 요청으로 Gemini를 사용한다. 이 발표 변경 이후 추가 검증은 사용자 요청에 따라 생략했다.
