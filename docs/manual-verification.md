# 구현 후 수동 확인

실행 계획이며 완료 기록이 아니다. 담당별로 실제 명령·환경·성공/실패·미확인을 README와 기능 PR에 남긴다. CI/자동 테스트 추가는 필수가 아니다.

| 영역 | 직접 확인할 동작 |
|---|---|
| 환경 | Python 3.12/의존성, Linux VM 커널/BTF, Docker 컨테이너 실행. 앱 기능과 구분 |
| 게시판 | CRUD·유효성 오류·없는 ID·SQLite 재시작 유지·컨테이너 기동 |
| 전송 입력 | sample JSONL replay, 깨진 줄 사이 정상 줄, 빈 객체/배열 거부, follow 미완결 줄/시작 전 줄 제외 |
| 수신 계약 | 토큰·instanceId, 201 신규/200 중복, 같은 ID 다른 내용 409, DB 실패에 성공 ACK 없음 |
| 전송 실패 | 동일 messageId 최대 3회 재시도, 4xx 비재시도, 401/403 종료, timeout·잘못된 ACK·회전 종료 |
| 정규화 | exec/exit·누락 필드·OTHER, 정책별 실측 매핑, sample/live·reportedAction/outcome 구분 |
| SaaS 저장 | 재시작 후 이벤트·스냅샷·분석 유지, 목록과 전체 범위 집계 일치 |
| 화면·AI | 시간 범위 고정, 새 이벤트에도 스냅샷/캡처 불변, 캡처 실패 중단, 실제 JSON+이미지 AI 호출 |

## 실제 Tetragon 검증

1. 정책 없이 고정 보호 파일을 읽는 probe가 READ_OK와 정상 종료를 반환하는지 확인한다.
2. 관찰 정책 적용 후 정상 읽기와 해당 파일의 실제 이벤트를 함께 확인한다.
3. live 전송기를 시작한 뒤 새 활동이 실제 SaaS에 도착하는지 확인한다. 임시 수신기 성공과 구분한다.
4. 관찰 정책 해제 후 대응 정책을 적용해 대상 프로세스·시각이 일치하는 이벤트와 실제 종료 결과를 기록한다.
5. 게시판 CRUD가 정상 유지되는지 확인한다.
6. 대응 정책 해제 후 같은 probe의 정상 복구를 확인한다.

프로세스 종료는 파일 읽기 완전 차단의 증거가 아니다. 외부 kill이나 예시 로그를 Tetragon 대응으로 기록하지 않는다. 핵심 검증 불가 시 미완료/Draft로 유지한다.

## 기록 형식

환경/버전, 실행 명령, 입력이 sample 또는 live인지, 직접 확인한 결과, 실패와 미확인, 정책 전후 증거를 기록한다. 비밀키·개인 원본 데이터는 저장하지 않는다.
