# Tetragon 기반 보안 모니터링과 대응 설계

## 목표와 완료 기준

로컬 Linux의 시연 서버에서 Tetragon으로 활동을 관찰하고, 미리 정한 정책으로 대상 프로세스에 대응한다. 우리 서비스는 이벤트 수집·화면 알림·AI 조사 안내를 제공한다.

완료 기준은 실제 이벤트의 대시보드 표시, 새 경고 알림, 정책에 따른 실제 대응 결과의 별도 확인, 선택 이벤트의 AI 설명이다. 현재는 구조·의존성 설정·문서만 준비됐으며 애플리케이션·정책은 미구현이다.

핵심 시나리오는 [시연용 파일 읽기](../demo/README.md)다. 기본 대응 목표는 접근한 probe 프로세스 종료이며, 파일 읽기 자체 거부와 구분한다. AI의 YAML 수정, 정책 자동 배포, 취약점 자동 수정, 실제 고객 관리, 외부 알림은 제외한다.

## 책임과 흐름

```text
Linux: 시연 서버 → 커널의 eBPF 프로그램 → 정책에 따른 관찰·대응
                              ↓
                       Tetragon Agent
                              ↓ JSONL
개발 호스트: 전송 모듈 → FastAPI 수신·변환·메모리 저장
                              ↓
                 대시보드 목록·상세·새 경고
                              ↓ 사용자 분석 요청
                 백엔드 → OpenAI → 조사 안내
```

- Tetragon Agent가 정책과 eBPF 프로그램을 관리한다. 대응은 미리 적용한 정책을 따라 커널에서 수행하며 백엔드·AI의 응답을 기다리지 않는다.
- 전송 모듈은 원본을 HTTP 봉투에 넣어 전달한다. 백엔드만 공통 이벤트로 변환한다.
- 백엔드는 시연 경고 정책명과 일치하는 이벤트를 attention으로 표시한다. AI는 경고 분류나 대응 결정을 변경하지 않는다.
- 대시보드는 최근 목록과 원본 상세를 표시한다. 외부 AI에는 선택한 요약 필드와 서버 설명만 전달한다.

## 배치와 저장

[선정한 기술 스택](tech-stack.md)은 Python 3.12/FastAPI, 기본 HTML·CSS·JavaScript, JSONL→HTTP, 메모리 최근 1,000건, 2초 폴링, OpenAI Responses API/gpt-5-mini다. 화면은 FastAPI에서 같은 주소로 제공한다.

macOS 개발 호스트와 Docker의 Linux VM은 별개다. Tetragon은 Linux 커널 활동을 관찰하고, 이벤트 파일만 호스트 전송기가 읽는다. 실제 커널·BTF·권한 지원과 공유 경로는 환경 담당자가 확인한다. Docker가 설치돼 있다는 사실만으로 Tetragon 실행을 확인한 것으로 보지 않는다.

전송 재시도·회전 복구·중복 제거·DB는 v1 범위 밖이다. 백엔드 재시작 시 데이터가 사라지고, 고빈도 상황에서 화면 알림이 누락될 수 있다. 단일 프로세스로 실행하며 이 제약을 시연 범위에 명시한다.

## 상태의 의미

| 정보 | 표현 |
|---|---|
| Tetragon 이벤트 | 설정된 활동을 관찰한 기록 |
| attention | 지정한 시연 경고 정책명에 해당함. 공격 확정 아님 |
| reportedAction | 실제 원본 이벤트에 보고된 대응 동작 |
| outcome=unknown | 이 서비스가 실제 작업 성공/실패를 확인하지 못함 |
| sample/live | 예시·재생 입력과 현재 Tetragon 출력을 구분 |

이벤트의 action이 있어도 파일 접근이 실제 거부됐다고 표시하지 않는다. Tetragon의 신호 전달과 작업 거부의 의미는 [공식 대응 문서](https://tetragon.io/docs/concepts/enforcement/)를 따른다. 실제 결과는 정책 전·후·해제 후의 프로세스/작업 결과로 별도 검증한다.

## 남은 실환경 확인

Tetragon 이미지와 Linux 커널의 호환 조합, 시연 파일 접근 훅/인자와 프로세스 범위, 실제 이벤트 매핑, 정책 적용·해제 명령, JSONL 공유 경로, OpenAI 키·모델 접근 권한과 실제 호출은 아직 확인해야 한다. 이는 구현 방향의 미정이 아니라 실환경에서 검증할 항목이다.
