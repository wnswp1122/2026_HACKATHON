# 대시보드 구현 안내

## 목표

한 화면에서 최근 이벤트, 조사할 경고, 원본 상세와 AI 조사 안내를 확인한다. 관찰·정책 설정·보고된 대응·실제 결과를 혼동하지 않도록 표시한다. **현재 화면 코드는 없다.**

기술: HTML/CSS/JavaScript ES modules. 백엔드가 화면과 정적 파일을 제공한다. [API 계약](../docs/api-contract.md)과 [실행 방법](../docs/local-development.md)을 먼저 읽는다.

## 화면 구성

```text
런타임 보안 모니터링      API 연결 상태 / 마지막 조회 시각
[새 경고 1건: 시연 정책과 일치]              [닫기]

최근 100건: [전체] [확인 필요] [실행] [파일] [네트워크]
시각       유형          대상/프로세스       상태       입력
12:30:12   프로세스 실행 /usr/bin/cat        관찰       예시

선택한 이벤트
발생 시각 / 수신 시각 / 인스턴스 / 부모 프로세스 / 정책명
경고 근거 / 보고된 대응 동작 / 결과: 확인 불가
[원본 JSON 펼치기]

서버 설명 [최대 2,000자 입력]
외부 AI에 전달: 경로·대상·이벤트 요약·서버 설명 (원본/인자 제외)
[AI 조사 안내 받기]
관찰 사실 | 가능한 해석 | 확인 사항 | 분석 한계
```

연결 상태는 백엔드 API의 상태다. Tetragon heartbeat가 없으므로 `Tetragon 정상 연결`을 표시하지 않는다. 카드 숫자는 가져온 최근 목록 기준이고 전체 공격 수가 아니다.

## 작성할 파일

- `index.html`: 화면 영역과 초기 빈 상태, `/static/src/main.js` module 로드.
- `styles.css`: 목록·상세·경고/관찰·예시 구분. 작은 화면에서 상세가 아래로 오도록 구성.
- `src/main.js`: 초기화, API 공통 오류 처리, 선택 이벤트 전달.
- `src/events/view.js`: 목록·필터·상세·주기 조회·새 경고 배너.
- `src/analysis/view.js`: 설명 입력, AI 요청·결과·오류.

목록은 요약 객체, 상세는 GET으로 원본을 포함해 받는다. DOM에는 외부 문자열을 textContent로 넣고 JSON도 텍스트로 보여준다. AI 결과를 HTML로 삽입하지 않는다.

## 데이터 흐름

시작 시 health와 목록 조회 → 첫 목록은 기존 데이터로 표시 → 이후 목록 요청이 끝난 뒤 2초 후 다음 요청 → 새 attention 이벤트가 있으면 배너. 여러 요청을 겹쳐 보내지 않는다. 목록 조회가 실패해도 이미 보이는 데이터를 지우지 않고 마지막 성공 시각과 오류를 표시한다.

선택 이벤트가 바뀌면 이전 분석 결과를 새 이벤트의 결과처럼 남기지 않는다. 이전 요청의 늦은 응답은 eventId를 확인해 무시하거나 이전 이벤트 상태에만 보관한다.
